# 告警追溯与推送格式

错误率按上游请求尝试计算，不按客户端请求的最终结果计算。状态码 0（无 HTTP 响应）、401、403、404、429 和 5xx 及以上沿用现有失败口径；切换后成功的请求仍可能包含失败尝试。

## 查看失败记录

请求日志保留“请求最终失败”筛选，新增“上游尝试失败（告警口径）”。后者自动按参与尝试的上游匹配，失败条件和上游条件必须落在同一次尝试上。也可用“上游匹配 → 参与尝试的上游”查看该上游全部尝试所在的请求。展开切换链查看每次状态码和错误信息。

通知设置新增“告警历史”。错误率告警快照保存固定统计窗口、阈值、尝试数、失败数、状态码分布、含失败尝试但最终成功的请求数，以及最多 100 个失败请求标识。点击“查看窗口内失败尝试”会带入上游和精确时间窗口。窗口为开始时间包含、结束时间不包含；按请求日志的创建时间计算。

快照与通知入队处于同一数据库事务，渠道投递完成不会删除快照。历史代表告警已生成，不代表渠道已送达。快照沿用现有告警事件保留期；源请求明细也受日志保留期约束。后续延迟写入的日志可能出现在同一窗口查询中，核对当时比例以快照为准。升级前未保存的快照无法补录。

## 提醒语义

首次、持续提醒、恢复后再次触发分别显示对应文案和提醒次数。有记录的本轮触发起点会显示持续时间。既有冷却、次数上限、样本门槛、连续确认和恢复规则不变。

## Markdown 渠道

2026-09-09 核对官方文档：

- [钉钉自定义机器人](https://open.dingtalk.com/document/robots/custom-robot-access)：已有 `msgtype=markdown`，调整为标题、加粗标签和分段详情。加粗标记只包围字段名称，冒号放在标记外，避免部分解析器将标记原样显示。
- [企业微信群机器人](https://developer.work.weixin.qq.com/document/path/91770)：支持 `msgtype=markdown`，正文为 `markdown.content`，UTF-8 正文上限 4096 字节。由原来的纯文本切换为 Markdown，超长内容按 UTF-8 边界截断并提示查看历史。
- 飞书、Slack、Discord 和通用 Webhook 本次保留既有消息协议；没有将钉钉的 Markdown 消息结构套用到其他渠道。

上游名称和详情中的 Markdown 特殊字符会转义。钉钉正文采用 18000 字节的保守上限。合并提醒保留每个上游的详情和提醒次数，单上游证据以历史中的原始快照为准。

本次迁移仅新增 `alert_events.payload` 可空 JSONB 列，无历史数据重写。代码和数据库迁移需随正常版本更新一起发布；本工作区不执行生产部署。

## 管理员发布本次变更

在实际生产 Compose 目录执行，先确认 `git status --short` 没有不明改动，核对 GitHub CI 通过且提交与本次交付一致。以下仅重建 D-API，不重启数据库或宿主代理。

```sh
set -e
release_stamp=$(date -u +%Y%m%dT%H%M%SZ)
release_backup="../dapi-backups/$release_stamp"
umask 077
mkdir -p "$release_backup"
cp -p .env compose.yaml "$release_backup/"
./deploy/backup.sh "$release_backup/database.sql.gz"
docker image tag "$(docker compose images -q dapi)" "dapi:rollback-$release_stamp"
git pull --ff-only origin main
docker compose build dapi
docker compose up -d --no-deps dapi
docker compose ps dapi
curl --fail --silent --show-error http://127.0.0.1:18083/healthz
```

容器健康后再验证公网入口、管理登录、告警历史和一次实际请求。真实通知渠道的外部送达应在管理员确认的测试渠道验证。数据库新增列兼容旧版应用；回退应用时保留新增列，使用保存的旧镜像，不删除数据库或命名卷。
