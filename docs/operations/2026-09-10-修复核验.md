## 复核修正与最新验证

复核发现完整 gzip 流被误计上游失败、预算拒绝后未读正文的排空绕过读期限、健康写库及锁等待绕过请求总时限，以及端到端测试查询日志早于落库的竞态。首轮单次测试通过没有覆盖这些边界，不能据此认定没有遗漏。

- 压缩响应：不透传调用方的 `Accept-Encoding`，由 Go Transport 协商 gzip 并透明解压，解析和下游正文使用同一份解压数据。三种流协议与非流式 JSON 回归均验证正文、响应头、用量和成功判定，并覆盖调用方 gzip、gzip/br、identity 三种声明。
- 预算拒绝：HTTP/1 明确关闭连接并结束读等待；只有成功读完正文才清理读期限。真实 TCP 覆盖 Content-Length、chunked、Expect: 100-continue，确认未发送正文也能收到完整 429，连接及时关闭。
- 健康更新：数据库写入和每上游锁等待共同受请求上下文及两秒上限约束，保留并发失败/成功的顺序；重试正文排空也响应取消。返回正文前和尝试之间检查总超时，未提交的响应返回 504/request_timeout。真实 HTTP 覆盖健康成功/失败写库挂起，另验证锁等待取消不落库、不泄漏引用。
- 端到端测试：客户端收到响应后等待处理器及其 deferred 日志写入结束，再检查费用、日志和告警。修正后带真实数据库的该用例连续 10 次 race 测试通过。

最新代码验证：`go test -race -count=1 ./...`（含隔离 PostgreSQL）、`go vet ./...`、Go 编译全部通过；前端 19 项 Vitest 与 vue-tsc 通过。本轮未修改前端和插件实现，未重复运行 Playwright、插件及漏洞审计，相关结果属于首轮验证。

## 第二次复核修正与优化（2026-09-10）

本次继续修复三项边界问题并落实四项优化：

- SSE 按空行分隔事件，合并多行 data，支持 LF/CRLF/CR、起始 BOM 和任意分片；单行/事件均有 1 MiB 上限，过大事件丢弃至下一事件，未终止事件不会在 EOF 或统计快照时被误派发。回归穷举每个分片位置并验证超长事件恢复。
- 模型列表统一总超时 504/request_timeout，客户端取消不再写成 500；移除无正文 GET 路径不必要的读取期限。
- 价格详情新增单档案 GET 接口，管理员鉴权和 404 均有真实数据库回归；编辑器加载、切换、关闭、卸载、失败和迟到响应均有验证，加载中禁止保存。
- 非流式响应新增独立的 512 MiB 默认容量预算（可配置），按实际扩容申请并同时计算新旧缓冲。预算不足返回 503/response_budget_exceeded，不计上游故障；配套当前容量/上限指标。
- 日志同步回退限制四个写入、64 个等待者和 100ms 等待期限，容量拒绝计入日志丢弃，指标及管理台展示累计次数与耗时。数据库不可用时不承诺零日志损失，避免无界同步写库拖垮请求处理。
- 报表缓存先检查命中，未命中才等待同查询加载并二次检查；命中返回不可变缓存的副本。新增回归确认命中不等待加载锁，且调用方不能修改缓存。

查询计划评估使用隔离 PostgreSQL 的 5 万行合成数据：分组 P95 与总计 P95 各扫描一次 5 万行，GROUPING SETS 候选扫描一次但仍需分组和排序。本次单次样本耗时约 51.5ms、22.7ms 和 65.3ms，仅验证计划结构，不据此承诺生产提速。本轮落实缓存命中路径优化，保留现有精确 P95 查询及统计口径；总计 P95 不能由分组 P95 相加或平均得到。

1. 改密与在途旧密码登录串行化：会话创建在事务内锁定管理员行并核对已验证的密码摘要；改密先提交时拒绝旧快照，登录先完成时其会话随后被改密撤销。真实数据库测试覆盖两种先后顺序。
2. 总超时覆盖网关鉴权，鉴权并发在查询数据库前准入；满额返回 429，超时返回 504，取消后释放名额。补查真实 TCP 发现未发送正文可阻塞鉴权错误返回，已通过关闭 HTTP/1 连接及结束读等待修正；Content-Length、chunked、Expect: 100-continue 的超时与满额共六个场景全部通过。
3. 新增迁移版本 4，为上游增加内部 `config_version`。编辑配置或手工保存模型递增版本；手工/周期探测、模型发现、网关健康回写及通知状态观察携带发起时版本，拒绝迟到结果，手工操作映射为 409。通知状态写入统一按上游行、事件状态行的顺序加锁，避免锁升级死锁。真实挂起 HTTP 探测回归确认修改凭据后旧结果不能熔断或暂停新配置。
4. 浏览器历史快照增加完整性标记，日志/用量首次加载未完成或失败后离开再后退，会重新请求；完整历史现场继续保留。
5. 图表定位标识加入上游、客户端与分组 ID 和分组名称，同一天不同分组可独立定位，日志下钻及后退保持一致。
6. Go 与 SQL 的 Base URL 归一化统一处理顺序，支持 IPv6 方括号与默认端口；真实 PostgreSQL 回归覆盖查询/片段、斜杠、非默认端口、编码路径和实际日志筛选。
